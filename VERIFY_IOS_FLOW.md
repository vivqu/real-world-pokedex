# Verifying the iOS Simulator (XcodeBuildMCP)

How to build, run, and visually verify the app on the iOS simulator. Use the **XcodeBuildMCP** tools — explore available tools rather than relying on the snippets below.

## Prerequisites

- Native project exists at `real-world-pokedex/ios/` (generated by `npx expo prebuild --platform ios`). Regenerate with prebuild if it's missing.
- XcodeBuildMCP tools are deferred: load a tool's schema via `ToolSearch` (`select:<tool_name>`) before calling it, or the call fails with `InputValidationError`.

## Flow

1. **Check session defaults first.** Call `session_show_defaults`. If workspace, scheme, and simulator are already set, skip to step 3.
2. **Configure defaults** (only if not set): use `discover_projs` and `list_sims` to find values, then `session_set_defaults`. For this project:
   - workspace: `real-world-pokedex/ios/realworldpokedex.xcworkspace`
   - scheme: `realworldpokedex`
   - bundleId: `com.vivqu.real-world-pokedex`
3. **Build + run:** call `build_run_sim` (no args needed once defaults are set).
4. **Verify visually:** call `screenshot` and inspect the rendered UI matches the expected change.

## Notes

- All other tools (logs, UI automation, stop/relaunch, etc.) are discoverable via the MCP tool list — search it instead of guessing.
- If a build fails, read the error from `build_run_sim` output before retrying; don't repeat the call verbatim.
- `build_run_sim` does a full native rebuild (slow). It's only *required* when native deps/config change — pure JS/TS edits can hot-reload via a running Metro server. Keep `build_run_sim` as the reliable default for verification.
