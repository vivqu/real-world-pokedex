# Verifying the Android Emulator (Expo + mobile-mcp)

How to build, run, and visually verify the app on an Android emulator. Build is driven by **Expo CLI** (Gradle under the hood); device interaction and verification use **mobile-mcp** (`@mobilenext/mobile-mcp`). Explore mobile-mcp's tool list via `ToolSearch` rather than relying on snippets.

## Prerequisites

- Android SDK installed; `ANDROID_HOME` set; `adb` and `emulator` on `$PATH`. Verify: `adb --version`.
- At least one AVD exists. List: `emulator -list-avds`. Create via Android Studio → Device Manager if none.
- Native project exists at `real-world-pokedex/android/` (generated by `npx expo prebuild --platform android`). Regenerate if missing.
- mobile-mcp is registered (`claude mcp add mobile-mcp -- npx -y @mobilenext/mobile-mcp@latest`). Verify with `claude mcp list` — it should report `✓ Connected`. Tools load via `ToolSearch` on demand.

## Flow

1. **Boot an emulator (let Expo do it).** Run `npx expo run:android` from `real-world-pokedex/`. Expo auto-detects a running emulator or boots the first AVD it finds, then runs `prebuild` (if needed) + Gradle + install + launches the app + starts Metro. First build is slow (10–30 min); subsequent builds are incremental.
2. **Verify visually.** Load `mcp__mobile-mcp__mobile_list_available_devices` and `mcp__mobile-mcp__mobile_take_screenshot` via `ToolSearch`. Call `mobile_list_available_devices` to grab the emulator's `id` (e.g. `emulator-5554`), then call `mobile_take_screenshot` with `{ device: "<id>" }` — the image is returned inline. Confirm the rendered UI matches the expected change.
3. **Iterate via Metro for JS/TS edits.** No rebuild needed for pure JS/TS changes — Metro hot-reloads. Re-run `npx expo run:android` only when native deps/config change.

## Notes

- **Don't boot the emulator manually with `-no-snapshot-save`** — the AVD's userdata won't persist, and APKs installed in that session are lost on shutdown. Prefer Expo's managed launch or Android Studio's Device Manager play button.
- If you do boot manually, omit `-no-snapshot-save` so installs persist across sessions.
- mobile-mcp's tools are deferred in this harness: load each via `ToolSearch` (`select:<tool_name>`) before calling, or the call fails with `InputValidationError`.
- Fallback if mobile-mcp is unreachable: `adb exec-out screencap -p > /tmp/android.png`, then `Read` the file. Slower round-trip and requires writing to disk, but works without the MCP server.
- If a build fails, read the Gradle error output before retrying. Common first-build issues: missing SDK platforms, wrong JDK version, slow CMake step on Apple Silicon (be patient on first run).
- Emulators use `10.0.2.2` to reach the host's loopback. If the dev client can't reach Metro, that's the address to use, not `localhost`.
